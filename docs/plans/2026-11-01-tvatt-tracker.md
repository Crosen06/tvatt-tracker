# Tvätt-tracker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app on a Raspberry Pi 4 (7" touch, 800×480) that tracks each household member's garments in the laundry basket, suggests compatible wash loads, and shows a wash timer with an on-screen "done" notice.

**Architecture:** One FastAPI process serves a REST API, an SSE stream and a prebuilt Svelte 5 SPA. SQLite + photo files live in a data dir outside the repo. The Pi shows the SPA in Chromium kiosk mode; phones on the LAN use the same SPA to photograph and tag garments.

**Tech Stack:** Python 3.11+ (Pi OS ships 3.11/3.13), FastAPI, uvicorn, Pillow, python-multipart, stdlib sqlite3, pytest, httpx; Svelte 5 + Vite (no SvelteKit); Playwright (Python) for UI checks.

**Spec:** `docs/specs/2026-11-01-tvatt-tracker-design.md`

## Global Constraints

- UI copy in Swedish; code, comments, commit messages in English.
- Household seed: Charlie, Kiki, Magnus.
- Tag values: `max_temp` ∈ {20, 30, 40, 50, 60, 90}; `color` ∈ {white, light, dark, colored}; `max_spin` ∈ {0, 400, 600, 800, 1000, 1200, 1400}; `care` ∈ {normal, synthetic, delicate, wool, hand}; `tumble_dry` bool.
- Seed programs: Bomull 40° (180 min, normal), Bomull 60° (200, normal), Syntet 40° (120, synthetic), Fintvätt 30° (60, delicate), Ull 30° (45, wool), Snabbtvätt 30° (30, normal).
- Setting `split_hot` default on: items ≥60° never grouped with items ≤50°.
- Data dir: env `TVATT_DATA`, default `~/tvatt-data` (`tvatt.db`, `photos/`, `photos/thumb/`).
- Only one running wash at a time (HTTP 409 otherwise).
- Times stored as UTC ISO-8601; the timer derives from `ends_at` in the DB.
- Kiosk viewport 800×480 landscape; touch targets ≥ 72 px on the kiosk.
- Pi never runs Node: built SPA is committed to `backend/app/static/`.
- Served on port 80 as a non-root systemd service; hostname `tvatt` → `http://tvatt.local`.

## Review Focus

1. **iPhone/Android photo formats (HEIC, huge JPEGs):** the client always re-encodes to JPEG ≤1200 px; the server accepts only JPEG/PNG/WebP and answers 415 with a Swedish message otherwise. → test in Task 4.
2. **Archiving a garment that is in the basket or in the running wash:** archiving removes it from the basket; archiving a garment in a running wash returns 409. → test in Task 4.
3. **Editing/deleting a program while a wash runs:** the wash keeps its own name/duration snapshot and its end time does not change. → test in Task 5.
4. **Pi clock vs. phone clock drift:** `GET /api/washes/current` includes `server_now`; the client computes the remaining time from server time, not its own clock. → test in Task 5, used in Task 7.
5. **Empty states:** no garments for a person, empty basket, single-item basket — API returns `[]`/one group, UI shows a Swedish empty-state text instead of a blank screen. → tests in Task 2 and Task 9.

### Task 2: Grouping logic

**Files:** Create `backend/app/grouping.py`, `backend/tests/test_grouping.py`

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) Item(id:int, person_id:int, max_temp:int, color:str, max_spin:int, care:str, tumble_dry:bool)`
  - `@dataclass(frozen=True) Prog(id:int, name:str, temp:int, care:str)`
  - `@dataclass Group(key:str, color:str, care:str, temp:int, spin:int, item_ids:list[int], program_id:int|None, no_dry_ids:list[int])`
  - `@dataclass Selection(group:Group|None, compatible_ids:list[int], conflicts:list[str])`
  - `care_class(care:str) -> str` – normal/synthetic → "standard", else itself
  - `suggest_program(care:str, temp:int, programs:list[Prog]) -> int|None` – programs with exactly that care and `temp <= group temp`; pick highest temp; ties → first in list
  - `group_items(items:list[Item], programs:list[Prog], split_hot:bool=True) -> list[Group]` – key = color + care class + band (`hot` if max_temp ≥ 60 and split_hot else `std`); temp = min max_temp; spin = min max_spin; care = "synthetic" if any synthetic in a standard group, "normal" if all normal, else the class; sorted by len(item_ids) desc then key; item_ids sorted
  - `check_selection(selected:list[Item], basket:list[Item], programs:list[Prog], split_hot:bool=True) -> Selection`

Conflict strings (exact Swedish copy, one per conflicting dimension): `"Olika färggrupper: {a} + {b}"` (labels vitt/ljust/mörkt/kulört, in tag order), `"{Klass} måste tvättas för sig"` (Fintvätt/Ull/Handtvätt), `"60° och varmare tvättas för sig"`. On conflict: `group=None`, `compatible_ids=[]`.

### Task 5: Suggestions and washes API

**Files:** Create `backend/app/routers/{suggestions,washes}.py`, `backend/tests/test_washes_api.py`.

**Interfaces:**
- Consumes: `grouping.group_items`, `check_selection`, `Item`, `Prog` (Task 2); `utcnow()` (Task 1).
- Endpoints:
  - `GET /api/suggestions` → list of `{key,color,care,temp,spin,program_id,item_ids,no_dry_ids,person_ids}` for basket items not in a running wash.
  - `POST /api/suggestions/check {garment_ids}` → `{group|null, compatible_ids, conflicts}`.
  - `POST /api/washes {program_id, garment_ids, temp, spin}` → 201 wash; 409 `"En tvätt är redan igång."` if one is running; 400 if any garment not in basket. Snapshots program name and duration; `ends_at = started_at + duration`.
  - `GET /api/washes/current` → `{wash: {...items: [garment JSON]} | null, server_now}`; returns the running wash (done or not; `is_done = server_now >= ends_at`).
  - `POST /api/washes/{id}/finish` → status `done`, its garments `in_basket=0`.
  - `POST /api/washes/{id}/cancel` → status `cancelled`, garments stay in basket.
  - All mutations publish `wash` and `garments`.
